Access haladó - Levéltári adatbázisok

Fejezet 2 Normalizálás alapjai

A normalizálás az adatbázis-tervezés alapvető módszere, amely megszünteti az ismétlődéseket és biztosítja az adatok konzisztenciáját. Ebben a fejezetben megtanuljuk a normalizálás alapelveit levéltári kontextusban.

2.1 Mi a normalizálás?

A normalizálás az adatok logikus táblákba szervezésének folyamata úgy, hogy:

  1. Minimalizáljuk az ismétlődést (redundanciát)
  2. Biztosítsuk az adatintegritást (konzisztenciát)
  3. Megkönnyítsük az adatok karbantartását (módosítás, törlés, beszúrás)

Egyszerűen: A normalizálás azt jelenti, hogy minden adatot a megfelelő helyre teszünk, és csak egyszer tároljuk.

2.2 A normalizálás szintjei

Az adatbázis-elméletben több normálformát különböztetünk meg. Mi most a gyakorlatban legfontosabb három szintet nézzük meg.

2.2.1 Első normálforma (1NF)

Alapelv: Minden mezőben egyetlen érték szerepel, nincs több értékű mező.

Rossz példa (nem 1NF):

┌─────┬───────────────┬───────────────────────────│  
│FondID│FondNév       │Állag                      │
├─────┼───────────────┼───────────────────────────┤
│  1  │I. ker.Tanács  │Ülések, Iratok, Határozatok│
│  2  │Pesti Színház  │Igazgató, Előadások        │
└─────┴───────────────┴───────────────────────────┘

Probléma: Az “Állag” mező több értéket tartalmaz egyetlen cellában!

Helyes (1NF):

┌─────┬─────────────────┬────────────┐
│FondID│FondNév         │ÁllagNév    │
├─────┼─────────────────┼─────────── ┤
│  1  │I. ker.Tanács    │Ülések      │
│  1  │I. ker.Tanács    │Iratok      │
│  1  │I. ker.Tanács    │Határozatok │
│  2  │Pesti Színház    │Igazgató    │
│  2  │Pesti Színház    │Előadások   │
└─────┴─────────────────┴────────────┘

Most minden mezőben egy érték van. ✅

Gyakori hiba: Többértékű mezők használata: “Ülések; Iratok; Határozatok” VAGY “Ülések, Iratok” stb. Ezeket mindig külön rekordokra kell bontani!

2.2.2 Második normálforma (2NF)

Alapelv: Az 1NF-en felül minden nem-kulcs mező teljes mértékben függ az elsődleges kulcstól.

Példa (nem 2NF - még mindig rossz):

Az előző “helyes” példa valójában még mindig problémás:

┌─────┬──────────────┬────────────┐
│FondID│FondNév      │ÁllagNév    │
├─────┼──────────────┼────────────┤
│  1  │I. ker.Tanács │Ülések      │
│  1  │I. ker.Tanács │Iratok      │
│  1  │I. ker.Tanács │Határozatok │
└─────┴──────────────┴────────────┘

Probléma: A FondNév ismétlődik! Az “I. ker. Tanács” háromszor szerepel.

Miért? Mert a FondNév csak a FondID-tól függ, nem az egész sorból (FondID + ÁllagNév).

Megoldás: Bontsuk két táblára!

tbl_Fondok:

┌─────┬─────────────┐
│FondID│FondNév     │
├─────┼─────────────┤
│  1  │I. ker.Tanács│
│  2  │Pesti Színház│
└─────┴─────────────┘

tbl_Állagok:

┌────────┬─────┬────────────┐
│ÁllagID │FondID│ÁllagNév   │
├────────┼─────┼────────────┤
│   1    │  1  │Ülések      │
│   2    │  1  │Iratok      │
│   3    │  1  │Határozatok │
│   4    │  2  │Igazgató    │
│   5    │  2  │Előadások   │
└────────┴─────┴────────────┘

Most a FondNév csak egyszer szerepel! ✅ Az állagok a FondID-val hivatkoznak rá.

2.2.3 Harmadik normálforma (3NF)

Alapelv: A 2NF-en felül nincs tranzitív függőség (nem-kulcs mezők nem függnek egymástól).

Példa (nem 3NF):

tbl_Iratok:
┌──────┬────────┬──────────┬──────────────┬──────────┐
│IratID│ÁllagID│IratCím   │ÁllagKeletkezés│IratDátum │
├──────┼────────┼──────────┼──────────────┼──────────┤
│  1   │   1    │Jegyzők.1 │1949-1956     │1956.10.23│
│  2   │   1    │Jegyzők.2 │1949-1956     │1956.11.04│
│  3   │   2    │Levél X   │1945-1989     │1970.05.12│
└──────┴────────┴──────────┼──────────────┼──────────┘

Probléma: Az ÁllagKeletkezés nem az IratID-tól függ, hanem az ÁllagID-tól! Ez tranzitív függőség.

Következmény: Az “1949-1956” ismétlődik minden iratban, ami az 1-es állaghoz tartozik!

Megoldás: Az ÁllagKeletkezés a tbl_Állagok táblába tartozik!

tbl_Állagok (helyesen):

┌────────┬─────┬────────────┬──────────────┬──────────┐
│ÁllagID │FondID│ÁllagNév   │KeletkezésÉvtől│Kelet.Évig│
├────────┼─────┼────────────┼──────────────┼──────────┤
│   1    │  1  │Ülések      │    1949      │   1956   │
│   2    │  1  │Iratok      │    1945      │   1989   │
└────────┴─────┴────────────┴──────────────┴──────────┘

tbl_Iratok (helyesen):

┌──────┬────────┬──────────┬──────────┐
│IratID│ÁllagID │IratCím   │IratDátum │
├──────┼────────┼──────────┼──────────┤
│  1   │   1    │Jegyzők.1 │1956.10.23│
│  2   │   1    │Jegyzők.2 │1956.11.04│
│  3   │   2    │Levél X   │1970.05.12│
└──────┴────────┴──────────┴──────────┘

Most az állag keletkezési éve csak egyszer szerepel (a tbl_Állagok táblában)! ✅

2.3 Levéltári példa: Fondok → Állagok → Iratok

Most alkalmazzuk a normalizálást a levéltári hierarchiára!

2.3.1 Kiindulás: Rossz struktúra (denormalizált)

Egyetlen tábla:

┌────┬───────────┬───────────────┬─────────┬──────────┬──────────┬───────────┐
│AZON│FondNév    │FondLeírás     │ÁllagNév │Évtől-Évig│IratCím   │DoboztárSz │
├────┼───────────┼───────────────┼─────────┼──────────┼──────────┼───────────┤
│ 1  │I.kerTanács   │Helyi tanács│Ülések   │1950-1990 │Jegyző.1  │123        │
│ 2  │I.kerTanács   │Helyi tanács│Ülések   │1950-1990 │Jegyző.2  │124        │
│ 3  │I.kerTanács   │Helyi tanács│Iratok   │1945-1989 │Levelezés │T 200      │
└────┴──────────┴────────────┴─────────┴──────────┴──────────┴───────────────┘

2.3.2 1. lépés: 1NF ellenőrzése

Kérdés: Van-e többértékű mező?

Ellenőrzés:

  • FondNév: “I. ker. Tanács” (egy érték)
  • ÁllagNév: “Ülések” (egy érték)
  • IratCím: “Jegyzőkönyv 1” (egy érték)

Eredmény: 1NF teljesül! Nincs vessző-elválasztott lista.

2.3.3 2. lépés: 2NF alkalmazása

Kérdés: Mi függ csak a FondID-tól?

Analízis:

  • FondNév: Csak a fond azonosítójától függ → külön táblába!
  • FondLeírás: Csak a fond azonosítójától függ → külön táblába!
  • ÁllagNév: Az állagtól függ, nem a fondtól közvetlenül → külön táblába!
  • IratCím: Az irattól függ → marad az Iratok táblában

Bontsuk szét:

tbl_Fondok:

┌──────┬──────────────┬─────────────────────┐
│FondID│FondNév       │FondLeírás           │
├──────┼──────────────┼─────────────────────┤
│  1   │I. ker.Tanács │Helyi tanács iratai  │
│  2   │Pest Színház  │Pesti Színház iratai │
└──────┴──────────────┴─────────────────────┘

tbl_IratokÁllagokkal (még nem kész!):

┌──────┬──────┬─────────┬──────────┬──────────┬───────────┐
│IratID│FondID│ÁllagNév │Évtől-Évig│IratCím   │DoboztárSz │
├──────┼──────┼─────────┼──────────┼──────────┼───────────┤
│  1   │  1   │Ülések   │1950-1990 │Jegyzők.1 │123        │
│  2   │  1   │Ülések   │1950-1990 │Jegyzők.2  │124       │
│  3   │  1   │Iratok   │1945-1989 │Levelezés │200        │
└──────┴──────┴─────────┴──────────┴──────────┴───────────┘

Probléma: Az ÁllagNév és Évtől-Évig még mindig ismétlődik! (1-2. sor)

2.3.4 3. lépés: 3NF alkalmazása

Kérdés: Mi függ az ÁllagID-tól (nem az IratID-tól)?

Analízis:

  • ÁllagNév: Az állagtól függ → külön táblába!
  • Évtől-Évig: Az állagtól függ → külön táblába!
  • IratCím: Az irattól függ → marad az Iratok táblában

Bontsuk tovább:

tbl_Állagok:

┌────────┬──────┬─────────┬──────────────┬──────────┐
│ÁllagID │FondID│ÁllagNév │KeletkezésÉvtől│Kelet.Évig│
├────────┼──────┼─────────┼──────────────┼──────────┤
│   1    │  1   │Ülések   │    1950      │   1990   │
│   2    │  1   │Iratok   │    1945      │   1989   │
│   3    │  2   │Igazgató │    1900      │   1950   │
└────────┴──────┴─────────┴──────────────┴──────────┘

tbl_Iratok (végső, helyes):

┌──────┬────────┬──────────┬───────────┬──────────────┐
│IratID│ÁllagID│IratCím    │DoboztárSz │Digitalizálva │
├──────┼────────┼──────────┼───────────┼──────────────┤

2.3.5 Végeredmény: Normalizált struktúra

Három tábla, három szint:

tbl_Fondok (FondID, FondNév, FondLeírás)
  │
  └─── kapcsolat: FondID
       │
       tbl_Állagok (ÁllagID, FondID, ÁllagNév, KeletkezésÉvtől, KeletkezésÉvig)
            │
            └─── kapcsolat: ÁllagID
                 │
                 tbl_Iratok (IratID, ÁllagID, IratCím, DoboztárSz, Digitalizálva)

Előnyök:

  • Minden fond adatai egyszer szerepelnek
  • Minden állag adatai egyszer szerepelnek
  • Minden irat adatai egyszer szerepelnek
  • Nincs ismétlődés, nincs redundancia
  • Könnyű karbantartás, frissítés, törlés

2.4 Normalizálási szabályok levéltárban

2.4.1 Általános elvek

1. Minden entitás külön táblába

  • Entitás: Önállóan létező dolog (fond, állag, irat, kutató, stb.)
  • Külön tábla: Minden entitásnak saját táblája van

Levéltári példák:

  • Fond → tbl_Fondok
  • Állag → tbl_Állagok
  • Irat → tbl_Iratok
  • Kutató → tbl_Kutatók
  • Látogatás → tbl_Látogatások

2. Nincs ismétlődés

Ha ugyanaz az adat többször szerepel → külön táblába!

Példa:

  • Ha az “I. ker. Tanács” fondnév 500 iratban szerepel → rossz! A tbl_Fondok táblában szerepeljen egyszer, és hivatkozzunk rá FondID-val.

3. Hierarchiák kapcsolatokkal

A levéltári hierarchiát (fond → állag → irat) kapcsolatokkal ábrázoljuk, nem ismétléssel!

Fond 1 ──────1:N──────> Állag 1
                        Állag 2
                        Állag 3

Állag 1 ─────1:N──────> Irat 1
                        Irat 2
                        Irat 3

4. Számított mezők kiszámítása, nem tárolása

Ne tároljuk a számítható adatokat!

Rossz példa:

tbl_Állagok:
ÁllagID, ÁllagNév, IratokSzáma

Miért rossz? Az IratokSzáma számítható! (COUNT(*) lekérdezéssel)

Helyes:

tbl_Állagok:
ÁllagID, ÁllagNév

Lekérdezésben:
SELECT ÁllagNév, COUNT(IratID) AS IratokSzáma
FROM tbl_Állagok
LEFT JOIN tbl_Iratok ON tbl_Állagok.ÁllagID = tbl_Iratok.ÁllagID
GROUP BY ÁllagNév

Kivétel: Nagy adatbázisoknál teljesítményi okokból néha mégis tároljuk a számított értékeket (“denormalizáció”). De ez haladó téma, és csak indokolt esetben!

# Hierarchikus űrlapok (főűrlap + alűrlap)

A hierarchikus űrlapok lehetővé teszik, hogy **egy űrlapon** lássuk és kezeljük a kapcsolódó adatokat. Például: egy fondot, annak állagait, és az állagok iratait - mind egy helyen!

## Mi az az alűrlap? {#mi-az-alurlap}

Az **alűrlap** (subform) egy űrlap, amely egy másik űrlapba van beágyazva.

**Szerkezet:**

┌──────────────────────────────────────────┐ │ Főűrlap (Fond adatai) │ ← Fond neve, leírása │ │ │ ┌────────────────────────────────────┐ │ │ │ Alűrlap 1 (Állagok) │ │ ← Az állagok listája │ │ - Állag 1 │ │ │ │ - Állag 2 │ │ │ │ - Állag 3 │ │ │ └────────────────────────────────────┘ │ │ │ └──────────────────────────────────────────┘


**Előnyök:**

-   Egy helyen látjuk a kapcsolódó adatokat
-   Könnyű navigáció (fond → állagok)
-   Automatikus szűrés (csak az aktuális fond állagait mutatja)

## Egyszerű hierarchikus űrlap: Fondok + Állagok {#egyszerű-hierarchikus}

### 1. lépés: Alap űrlap készítése (Fondok)

**Navigációs panelben:** Kattintsunk a `tbl_Fondok` táblára (NE nyissuk meg!)

**Létrehozás** → **Űrlap** gomb

Automatikusan létrejön egy űrlap. **Mentés:** `frm_Fondok`

### 2. lépés: Alűrlap hozzáadása

**Tervezési nézetre váltás**

**Alűrlap beszúrása:**

1.  **Tervezés** fül → **Vezérlők** csoport → **Alűrlap/Aljelentés** ikon
2.  Kattintsunk az űrlap alsó részére (ahol az alűrlapot szeretnénk)
3.  Megjelenik az **Alűrlap varázsló**

**Alűrlap varázsló - 1. lépés:**

-   "Meglévő tábla vagy lekérdezés használata" ← válasszuk ezt
-   **Tovább**

**2. lépés:**

-   **Tábla/lekérdezés:** `tbl_Állagok`
-   **Elérhető mezők:** Vigyük át ezeket:
    -   ÁllagNév
    -   KeletkezésÉvtől
    -   KeletkezésÉvig
-   **Tovább**

**3. lépés:**

-   "Kapcsolat definiálása magamnak" ← válasszuk ezt
-   Fő űrlap mezője: **FondID**
-   Alűrlap mezője: **FondID**
-   **Tovább**

**4. lépés:**

-   Alűrlap neve: `sub_Állagok`
-   **Befejezés**

### Eredmény

Most van egy űrlapunk, ahol:

# Kombinált listák (Combo Box)

A kombinált listák (combo box) az adatbevitel egyik leghatékonyabb módszere. Ahelyett, hogy begépelnénk az állag nevét vagy fond azonosítóját, egyszerűen kiválasztjuk egy legördülő listából!

## Mi a combo box? {#mi-combo}

A **combo box** (kombinált lista) egy legördülő mező, amely:

- Megjeleníti a választható értékek listáját
- Megakadályozza az elgépelést
- Biztosítja, hogy csak érvényes értékek kerüljenek be
- Felhasználóbarát (nem kell ID számokat megjegyezni!)

**Példa:**

ÁllagID: [Tanácsi ülések jegyzőkönyvei ▼] ← combo box │ │ │ Tanácsi ülések jegyzőkönyvei │ ← Legördülő lista │ Tanácsi hivatalos iratok │ │ Igazgatósági iratok │ │ Előadási iratok │ └─────────────────────────────────┘


**Amit látunk:** Az állag neve ("Tanácsi ülések...")  
**Amit tárol:** Az ÁllagID szám (1, 2, 3...)

## Combo box létrehozása varázslóval {#combo-varazslo}

## Combo box SQL-je {#combo-sql}

A combo box varázsló SQL lekérdezést készít a háttérben. Nézzük meg!

**Tervezési nézetben:**

1. Kattintsunk a combo box-ra
2. **Tulajdonságlap** (F4)
3. **Adatok** fül → **Sorforrás** tulajdonság

**Látjuk az SQL-t:**

```sql
SELECT tbl_Állagok.ÁllagID, tbl_Állagok.ÁllagNév
FROM tbl_Állagok
ORDER BY tbl_Állagok.ÁllagNév;

Ez azt mondja:

  • SELECT ÁllagID, ÁllagNév: Ezt a két mezőt kérd le
  • FROM tbl_Állagok: A tbl_Állagok táblából
  • ORDER BY ÁllagNév: Rendezd ÁllagNév szerint

2.6 Fejlettebb combo box: Fond + Állag együtt

Most készítsünk egy combo box-ot, amely több mezőt jelenít meg egyszerre!

Példa: Az állag nevét ÉS a fond nevét is lássuk:

Állag: [Tanács iratok - Tanácsi ülések jegyzőkönyvei  ▼]

2.6.1 SQL módosítása

A combo box Sorforrás tulajdonságát írjuk át:

SELECT tbl_Állagok.ÁllagID, 
       tbl_Fondok.FondNév & " - " & tbl_Állagok.ÁllagNév AS ÁllagTeljes
FROM tbl_Fondok 
INNER JOIN tbl_Állagok ON tbl_Fondok.FondID = tbl_Állagok.FondID
ORDER BY tbl_Fondok.FondNév, tbl_Állagok.ÁllagNév;

Magyarázat:

  • FondNév & " - " & ÁllagNév: Összefűzi a két nevet
  • AS ÁllagTeljes: Elnevezi az eredményt
  • INNER JOIN: Összekapcsolja a két táblát

Tulajdonságok beállítása:

  • Oszlopszám: 2
  • Oszlopszélességek: 0cm;8cm (első oszlop rejtve, második széles)
  • Kötött oszlop: 1 (az ÁllagID-t tárolja)
