Access haladó - Levéltári adatbázisok

Fejezet 6 Műveleti lekérdezések

A műveleti lekérdezések módosítják az adatokat (szemben a szelekciós lekérdezésekkel, amelyek csak lekérdeznek). Négy főbb típust különböztetünk meg: frissítési, hozzáfűzési, törlési és táblakészítő lekérdezéseket.

KRITIKUS FIGYELMEZTETÉS!

A műveleti lekérdezések VISSZAVONHATATLANOK! Az alábbi műveletek után nincs “Visszavonás” (Ctrl+Z)!

KÖTELEZŐ lépés MINDEN műveleti lekérdezés előtt: 1. Biztonsági mentés készítése 2. Tesztelés SELECT lekérdezéssel 3. Ellenőrzés kis mintán

Soha, semmilyen körülmények között ne futtassunk műveleti lekérdezést mentés nélkül!

6.1 Biztonsági mentés készítése

MINDEN műveleti lekérdezés előtt készíts biztonsági mentést!

6.1.1 Módszer 1: Adatbázis másolása (AJÁNLOTT)

Időigény: 1 perc
Legegyszerűbb, legbiztosabb módszer

Lépések:

1. ZÁRD BE az Access adatbázist teljesen!
   - Fájl → Bezárás
   - VAGY Alt+F4

2. Windows Intézőben navigálj az adatbázis mappájába
   - pl. C:\Levéltár\Adatbázisok\

3. JOBB egérgomb az .accdb fájlon → Másolás
   - VAGY Ctrl+C

4. JOBB egérgomb üres területen → Beillesztés
   - VAGY Ctrl+V

5. Nevezd át a másolatot:
   Eredeti: Levéltár_Állomány.accdb
   Backup:  Levéltár_Állomány_BACKUP_2024_03_16.accdb
            ↑ Dátummal ellátva!

6. Nyisd meg újra az EREDETI fájlt

Eredmény: Most van egy biztonságos másolatod!

Ha elrontod a műveleti lekérdezést: - Zárd be az eredeti fájlt - Töröld az eredeti fájlt - Nevezd át a backup-ot az eredeti névre - Nyisd meg → vissza vagy a kiindulópontnál!

6.1.2 Módszer 2: Tömörítés és Másolás (haladóknak)

1. Access-ben: Fájl → Információk → Adatbázis tömörítése és javítása
2. Várj, amíg befejeződik (~10-30 másodperc)
3. Fájl → Mentés másként → Adatbázis mentése → Tallózás
4. Mappa: C:\Access_Backups\
5. Fájlnév: Levéltár_backup_2024_03_16.accdb
6. Mentés

Előny: A backup tömörített, kisebb méretű
Hátrány: Lassabb (tömörítés időigényes)

6.1.3 Biztonsági mentési stratégia

Ajánlott struktúra:

C:\Levéltár\
  ├─ Adatbázisok\
  │   └─ Levéltár_Állomány.accdb  ← AKTUÁLIS fájl
  │
  └─ Backups\
      ├─ 2024_03_16_1000_előtte_frissítés.accdb
      ├─ 2024_03_16_1030_előtte_törlés.accdb
      └─ 2024_03_15_napi_backup.accdb

Névkonvenció: - ÉÉÉÉ_HH_NN_ÓÓPP_megjegyzés.accdb - Példa: 2024_03_16_1045_frissítés_előtt.accdb

Tipp: A Windows automatikusan időbélyeggel látja el a fájlokat (“Módosítva” oszlop), de a fájlnévben is szerepeltessük a dátumot/időt a könnyebb azonosítás miatt!

6.2 Frissítési lekérdezés (Update Query)

A frissítési lekérdezés meglévő rekordok mezőit módosítja.

Időigény: 10-15 perc
Veszélyesség kockázata: MAGAS - visszavonhatatlan!

6.2.1 Példa: Doboztár számok előtagának módosítása

Feladat: Az összes “TB-” kezdetű doboztár számot változtassuk “TANK-” előtagúra!

Előtte:

┌──────────────┐
│ DoboztárSzám │
├──────────────┤
│ TB-123       │
│ TB-124       │
│ TB-200       │
│ SZ-001       │ ← Ezt NE módosítsa!
└──────────────┘

Utána:

┌──────────────┐
│ DoboztárSzám │
├──────────────┤
│ TANK-123     │ Módosítva
│ TANK-124     │ Módosítva
│ TANK-200     │ Módosítva
│ SZ-001       │ Változatlan
└──────────────┘

6.2.2 1. LÉPÉS: Biztonsági mentés (KÖTELEZŐ!)

Lásd fent a "Biztonsági mentés készítése" fejezetet!
→ Készíts mentést MOST!

6.2.3 2. LÉPÉS: Tesztelés SELECT lekérdezéssel

NE kezdd frissítéssel! Először nézd meg, milyen rekordokat fog érinteni!

Új lekérdezés létrehozása:

1. Létrehozás fül (felső menüszalag)
2. Lekérdezéstervezés gomb

Képernyő: “Tábla megjelenítése” ablak

3. Dupla klikk: tbl_Iratok
4. Bezárás gomb

Képernyő: Lekérdezéstervező (felül tábla, alul rács)

Tervezői nézetben:

5. tbl_Iratok táblából húzd be a DoboztárSzám mezőt az alsó rácsba
   (dupla klikk a DoboztárSzám mezőre)

6. Alsó rács "Feltétel" sorába írd be: Like "TB-*"

Rács kinézete:

┌────────────────┐
│ Mező:          │ DoboztárSzám
│ Tábla:         │ tbl_Iratok
│ Megjelenítés:  │ ☑
│ Feltétel:      │ Like "TB-*"
└────────────────┘

Váltás SQL nézetre (opcionális, ellenőrzéshez):

7. Jobb felső sarok: "Nézet" ikonok → "SQL nézet"

SQL kód:

SELECT DoboztárSzám
FROM tbl_Iratok
WHERE DoboztárSzám Like "TB-*";

Tesztelés:

8. Futtatás (!) gomb (Tervezés fül, bal oldalt)
   VAGY F5

Eredmény (Adatlap nézet):

┌──────────────┐
│ DoboztárSzám │
├──────────────┤
│ TB-123       │
│ TB-124       │
│ TB-200       │
└──────────────┘

Rekordok: 3

Ellenőrzés: - Pontosan ezeket a rekordokat akarod módosítani? - Nincs benne véletlen olyan rekord, amit NEM szeretnél? - Hány rekord? (jegyezd meg: 3 db)

Ha NEM jók az eredmények: - Módosítsd a feltételt - Futtasd újra - Ellenőrizd újra

6.2.4 3. LÉPÉS: Számított mező tesztelése

Most nézzük meg, mi lesz az ÚJ érték!

Váltás Tervezői nézetre:

Nézet ikon → Tervezői nézet

Új számított mező hozzáadása:

1. Kattints az üres oszlopra (DoboztárSzám mellett)
2. "Mező" sorba írd be:
   ÚjÉrték: "TANK-" & Mid([DoboztárSzám],4)
   ↑ Ne felejtsd el az elején: "ÚjÉrték:"

Mit jelent az Mid([DoboztárSzám],4) függvény? - Mid() = középső karakterek kivonása - [DoboztárSzám] = a mező neve - 4 = a 4. karaktertől kezdve (0 az elejétől!) - “TB-123” → 4. karakter: “1” - Eredmény: “123” - "TANK-" & = Elé írjuk a “TANK-” szöveget - Teljes eredmény: “TB-123” → “TANK-123”

Futtatás:

3. Futtatás (!) gomb

Eredmény:

┌──────────────┬───────────┐
│ DoboztárSzám │ ÚjÉrték   │
├──────────────┼───────────┤
│ TB-123       │ TANK-123  │ Helyes!
│ TB-124       │ TANK-124  │ Helyes!
│ TB-200       │ TANK-200  │ Helyes!
└──────────────┴───────────┘

Ellenőrzés: - Az ÚjÉrték oszlop minden sora helyes? - A “TANK-” prefix mindenütt megvan? - A számok megmaradtak (123, 124, 200)?

Ha hibás: - Módosítsd a számított mező kifejezését - Futtasd újra - Ellenőrizd

6.2.5 4. LÉPÉS: Átváltás FRISSÍTÉSI lekérdezésre

MOST FIGYELEM! Innentől veszélyes terület!

1. Tervezés fül (felső menüszalag)
2. "Lekérdezés típusa" csoport → "Frissítés" gomb
   ↑ Ikon: ceruza tábla fölött

Képernyő: A lekérdezéstervező MEGVÁLTOZIK!

Előtte (SELECT):

┌────────────┬────────────┐
│Mező        │ Mező       │
│Tábla       │ Tábla      │
│Megjelenítés│Megjelenítés│
│Feltétel    │ Feltétel   │
└────────────┴────────────┘

Utána (UPDATE):

┌────────────────┐
│ Mező           │
│ Tábla          │
│ Frissítés      │ ← ÚJ SOR!
│ Feltétel       │
└────────────────┘

Beállítások:

3. DoboztárSzám oszlop "Frissítés" sorába írd be:
   "TANK-" & Mid([DoboztárSzám],4)

4. Töröld az "ÚjÉrték" oszlopot (ha van)!
   - Kattints az oszlop fejlécére
   - Delete billentyű

Rács végső állapota:

┌────────────────┐

6.6 Hibaelhárítás

6.6.1 H1: “Túl sok rekord frissítene/törölne”

Probléma: A lekérdezés több rekordot módosítana, mint vártad.

Példa:

SELECT teszt: 3 rekord
UPDATE megerősítés: 300 rekord ← HIBA!

Ok: A WHERE feltétel hibás vagy hiányzik!

Megoldás:

1. NE futtasd a lekérdezést!
2. Kattints "Nem" a megerősítő ablakban
3. Ellenőrizd a WHERE feltételt
4. Futtasd újra SELECT-tel
5. Csak ha egyezik a szám, futtasd UPDATE-tel!

6.6.2 H2: “Típuseltérés a kifejezésben”

Probléma: A frissítési kifejezés nem kompatibilis a mező típusával.

Példa:

UPDATE tbl_Iratok
SET DigitalizálásDátuma = "2024-01-15"  ← HIBA! Szöveg, nem dátum!

Megoldás:

-- HELYES:
SET DigitalizálásDátuma = #2024.01.15#  ← Dátum literál!

Dátum formátumok: - Access: #YYYY.MM.DD# vagy #MM/DD/YYYY# - Magyar: #2024.03.16# - Angol: #03/16/2024# - ROSSZ: "2024-03-16" (szöveg!)

6.6.3 H3: “Kulcs megsértés”

Probléma: A frissítés ütközik egy elsődleges kulccsal vagy egyedi indexszel.

Példa:

UPDATE tbl_Iratok
SET Jelzet = "K-150"  ← HIBA! K-150 már létezik!
WHERE IratID = 5;

Megoldás:

1. Ellenőrizd, hogy az új érték nem lesz-e duplikált!
2. Használj egyedi értéket:
   SET Jelzet = "K-" & [IratID]  ← Minden rekordnak más lesz

6.6.4 H4: “Referenciális integritás megsértése”

Probléma: Nem törölhető a rekord, mert másik tábla hivatkozik rá.

Példa:

DELETE FROM tbl_Állagok WHERE ÁllagID = 1;
-- HIBA! tbl_Iratok 15 rekordja hivatkozik erre az állagra!

Megoldás:

Opció A: Töröld előbb a hivatkozó rekordokat

-- 1. lépés: Töröld az iratokat
DELETE FROM tbl_Iratok WHERE ÁllagID = 1;

-- 2. lépés: Most már törölheted az állagot
DELETE FROM tbl_Állagok WHERE ÁllagID = 1;

Opció B: Lépcsőzetes törlés bekapcsolása

1. Adatbázis-eszközök → Kapcsolatok (Ctrl+R)
2. Dupla klikk a kapcsolatvonalra
3. ☑ Lépcsőzetes törlés a kapcsolódó rekordokban
4. OK
5. Most a DELETE automatikusan törli a hivatkozó rekordokat is!

Vigyázat a lépcsőzetes törléssel!

Ha bekapcsolod, akkor egy állag törlése AUTOMATIKUSAN törli az összes hozzá tartozó iratot is! Ez veszélyes lehet!

6.6.5 H5: “0 rekord frissült/törlődött”

Probléma: A lekérdezés lefutott, de nem módosított semmit.

Példa:

"0 sort fog frissíteni."

Ok: A WHERE feltétel egy rekordra sem igaz!

Megoldás:

1. Futtasd SELECT-tel ugyanazzal a WHERE-rel:
   SELECT * FROM tbl_Iratok WHERE DoboztárSzám Like "XYZ-*";

2. Ha üres → nincs ilyen rekord!
   
3. Ellenőrizd:
   - Helyes a mező neve? (DoboztárSzám vs DoboztárSzam)
   - Helyes a feltétel? ("TB-*" vs "TB*")
   - Van egyáltalán ilyen érték? (Keress rá Ctrl+F-fel)

6.6.6 H6: “A lekérdezés sérült”

Probléma: Az Access nem tudja értelmezni a lekérdezést.

Ok: SQL szintaktikai hiba.

Megoldás:

1. Váltás SQL nézetre
2. Ellenőrizd:
   - Minden zárójel páros? ( ) [ ]
   - Minden idézőjel páros? " "
   - Nincs felesleges vessző a végén?
   - A mezőnevek helyesek? [DoboztárSzám] vs [DoboztarSzam]

3. Másold ki az SQL-t egy szövegszerkesztőbe
4. Keress szintaktikai hibákat
5. Javítsd, másold vissza

       COUNT(tbl_Iratok.IratID) AS IratokSzáma,
       SUM(IIf([Digitalizálva]=True,1,0)) AS DigitalizáltIratokSzáma
INTO tbl_FondStatisztika
FROM (tbl_Fondok 
LEFT JOIN tbl_Állagok ON tbl_Fondok.FondID = tbl_Állagok.FondID)
LEFT JOIN tbl_Iratok ON tbl_Állagok.ÁllagID = tbl_Iratok.ÁllagID
GROUP BY tbl_Fondok.FondNév;

Elvárt eredmény: Egy új tbl_FondStatisztika tábla fond-szintű adatokkal.
